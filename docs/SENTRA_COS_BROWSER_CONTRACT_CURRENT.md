O patch `integrations/codex_chatgpt_web/sentra-upstream.patch` será a integração; `upstream.json.patch_files` permanece idêntico, upstream puro preservado. ## APIs internas requeridas ao coordenador

Mesmo bearer privado e validação de capability/trace/lease usados em `/internal/turn/browser-start`. Prefixo `/internal/turn/browser-`:

* `preflight`: POST `{capability,traceId,submission_index,prompt,prompt_sha256,document_id,identity_epoch,conversation_id,model,effort,surface_id}`. `prompt` é o texto físico transformado pelo upstream, apenas no loopback privado e nunca em log; o host valida SHA antes de armazenar intenção protegida. Documento/epoch são marcadores da página adquirida, nunca conta. Host resolve owner/workspace/Run/Operation/perfil/conta a partir do Browser Host autenticado. Retorna `{ok:true,state:'READY',request_id,account_verified:true,document_id,identity_epoch,prompt_sha256,submission_index}` SOMENTE após admission/idempotência/grant/lease e prova independente atual de conta. Model/effort são seleção observada no worker, não plano/conta.
* `sending`: POST binding acima + `request_id`; retorna `{ok:true,state:'SENDING',request_id,document_id,identity_epoch,prompt_sha256,submission_index}` somente após persistir fence. HTTP 200 sem schema/ACK exato NÃO permite efeito. ACK perdido não repete POST nem clique.
* `receipt`: POST binding + `request_id,message_id,observed_request_id,conversation_id,images_attached`. Message/request/conversation provêm do modelo React committed da página (não trace, texto, URL ou UUID criado pelo produtor). Hash do conteúdo observado deve igualar hash do prompt. Host deve validar vínculo autenticado e aceitar receipt sobre mesma Operation, em contrato V2 existente; retorna `{ok:true,state:'SENT',request_id,message_id}`. Ausência de metadata mantém UNCONFIRMED; nunca inventar message ID. Conta verificada é pré-condição host separada.
* `failure`: POST binding + `request_id?`, `may_have_sent:boolean`, `reason` limitado e sem texto de prompt. Registra FAILED pré-Send ou UNCONFIRMED após fence. É sinal conservador, nunca prova `not-run` ou licença para retry.
* `answer`: POST binding + `{request_id,observed_request_id,conversation_id,message_id,revision,body,complete,parent_user_message_id?}`; `message_id` é ASSISTANT observado, diferente do user receipt. `observed_request_id` mantém request observado no user. Assistant precisa metadata.request_id igual ou parent_id explícito igual ao user message; nenhum ID derivado de seletor/turn/SSE. `parent_user_message_id` só enviado quando parent_id realmente observado; backend deve passá-lo ao `WebSendAuthority.answer` e fornecer assistant_attestor host independente que confirme o vínculo atual. Revisão cresce só quando corpo observado muda ou finaliza. Retorno necessário `{ok:true,state:'ANSWERING'|'ANSWERED',job_id,answer_message_id,answer_revision}` (IDs/revisão persistidos devem ser projetados pelo status backend). Gateway deve adicionar `ok:true` somente após sucesso. Complete somente após DOM completion e antes do broker commit; missing assistant proof bloqueia completion durável. Corpo loopback privado, nunca logs.

P1 observado no teste de integração física Worker→Gateway real temporário: `WebSendAuthority.status()` omitiu `answer_message_id`/`answer_revision`, apesar de a tabela persistir ambos. Gateway adicionava ok:true e parent corretamente, mas ACK parcial retornava sem IDs/revisão e Worker rejeitava `sentra_answer_ack_invalid`. Coordenador/backend deve projetar esses dois campos persistidos (nenhuma inferência/UUID novo). Reprodução: `tests/unit/test_sentra_cos_durable_worker_gateway.py`, com SENTRA_BROWSER_QA_TREE apontando ao tree criado pelo preparo. Não relaxar validação do Worker para esconder falha de contrato. Resultado atualizado da reexecução ficará no relatório final.

As APIs não substituem register/tool/prepare/complete existentes. Browser-complete e broker-complete devem exigir receipts pertinentes, mantendo SSE/Operation e grants originais. Não criar Run/Operation duplicados. O produtor revalida documento e seleção depois dos awaits antes de Send. Um reload muda document/epoch, mesmo na mesma URL.

Transição acordada: `client_metadata.sentra_durable_web === true` percorre adapter → helper IPC → BrowserTurn.sentraDurableWeb.
